# Product change log

`changelog/` is reserved for the list of actual app and product changes. Each material change gets its own dated Markdown file. Use `YYYY-MM-DD-short-topic.md` filenames.

Every entry should include:

- **Status** — proposed, accepted, superseded, or rejected;
- **Change** — what changed in the product or implementation;
- **Context** — what prompted the change;
- **Impact** — what users, content, architecture, or operations are affected; and
- **Sources** — links when the change depends on external research.

Do not silently rewrite an old decision. Add a new dated entry when a decision changes.

Research-only notes belong in `research/` instead.
